# 网页设计与新手可读性约定

本页记录 BatteryReviewForge 网站自己的设计决策。参考 Apple 的公开[设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles)、[排版](https://developer.apple.com/design/human-interface-guidelines/typography)、[布局](https://developer.apple.com/design/human-interface-guidelines/layout)、[界面文字](https://developer.apple.com/design/human-interface-guidelines/writing)和[基础界面建议](https://developer.apple.com/design/tips/)；这些是设计参考，不意味着本站由 Apple 制作或认可，也不照搬 Apple 的页面素材、标题和商标。

## 阅读顺序

1. 第一屏说清用户能完成什么，再给“开始使用”和“先看样图”两个选择。
2. 首屏只放一张真实由本项目代码生成的演示图。图的来源、虚构状态和放大入口紧邻图面；不把多张科学图旋转叠压成装饰。
3. 下一屏按“有数据 / 有现成图 / 准备写综述”选择任务。技能名称、GitHub 和开发细节放到后面。
4. 安装页面一次只显示当前软件和系统的下一步；允许返回、重新选择、复制任务句。
5. 数据归属、上传、水印、演示与论文使用分别给一句可理解的回答，再链接完整说明。

## 标题与文字

- 首页 `h1`：用户收益，短句，读完能知道为什么继续。当前为“少花时间排图。多花时间想问题。”
- 一级页面 `h1`：当前任务或内容，不写抽象口号。例如“几步装好，先画一张。”
- `h2`：回答“这一屏做什么”；`h3`：对应一个材料或动作。所有按钮使用动词，例如“开始使用”“查看所有样图”。
- 初次出现时用“组合图”，必要时再附 `Figure`。网站避免把 `panel`、`harness`、`manifest` 作为新手操作前提；术语保留在技能和开发者页面。
- 文字保持诚实：网站本身没有上传框，不写“上传到本站”；在线 Agent 如何处理用户文件，由具体软件的设置决定。合成样图总在图旁标“虚构演示数据”。

## 视觉尺寸

| 元素 | 当前设计值 | 为什么 |
| --- | --- | --- |
| 内容宽 | 最多 1160 CSS px | 图能放大，正文不会拉成过长的一行 |
| 正文 | 16–19 CSS px | 先保证中文正常阅读，不靠极细字制造“高级感” |
| 首页标题 | 44–78 CSS px 自适应 | 大小层级清楚，手机不横向溢出 |
| 子页标题 | 34–52 CSS px 自适应 | 同一层级跨页面一致 |
| 按钮/主要链接 | 最小高度 44–48 CSS px | 触控更容易命中 |
| 科学图 | 按原始宽高比完整显示 | 不用 `cover` 裁掉刻度、图例或比例尺 |

文字色 `#1d1d1f`，正文次级色 `#51545a`，操作蓝 `#075fb6`，背景白与 `#f5f5f7`。蓝色只标识操作；科研图自己的颜色按样品和数据含义使用。系统字体栈适配 macOS、Windows 与常见中文字体，避免在线字体加载失败或字形替换。视觉层级主要由字号、字重、留白与对齐建立，不依赖渐变、阴影和大量图标。

## 人性化检查

- 导航在窄屏变成文字“菜单”，避免只有汉堡图标；站内搜索有文字标签和键盘快捷键，支持 Esc 关闭与焦点返回。
- 页面有跳过导航链接、明确的焦点轮廓和减少动态效果模式。
- 在 320、390、768、1024 和桌面宽度验收无横向滚动、控制不相撞、正文不被遮盖；重点检查 200% 放大后的布局。
- 科学图在手机上可能无法直接读清每个刻度，所以必须能点开 SVG 放大；不把缩略图当作最终可读性证据。
- 新手和开发者有不同入口：安装、试图和帮助留在本网站；仓库源码从“开发者入口”访问。

## 图片使用

首页科学图必须来自可追溯脚本与数据，保持完整坐标、单位和比例。概念性小插画可以使用生成模型或原创 SVG，但不能冒充显微照片、实验结果、TOF-SIMS 或原始测量。本版用产品实际生成的论文图作为主体，避免再加一层容易误导的 AI 风格插画。
